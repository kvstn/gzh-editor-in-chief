# gzh-editor-in-chief

公众号文章**责任编辑** skill。把传统报纸/杂志的出版前终审机制，落地成可执行的检查清单。

灵感来自一个很朴素的观察：写稿的人最难的不是写不出来，是**发散**——一篇文章塞三个观点、字数超硬门槛、段落跑题。这个 skill 就是那最后一道卡死。

## 解决什么

| 问题 | 会被哪项打回 |
|---|---|
| 字数超限| 第 1 维（硬门槛） |
| 一篇文章讲三个观点 | 第 2 维 观点集中度 |
| 段落跑题、凑字数 | 第 4–5 维 主线/逻辑链 |
| 议论文写成四不像 | 议论文体专项 24 项 |
| 干货文写成评论 | 垂直干货 E 组 8 项 |
| 通篇 AI 味、升华收尾 | D组风格锁 |

## 三层结构

```
12 维通用清单（所有文章都跑）
  ├─ 议论文体专项 24 项 ── 行业观点 / 趋势判断 / 机制拆解 / 方法论
  ├─ 垂直干货 E 组 8 项 ── 交付物是「一组可执行的动作或判据」
  └─ 双跑 ── 前半论证判断、后半给操作顺序（垂直文多数属此类）
```

**先判文体，再决定加跑哪个专项**——用错尺子会把一篇合格的干货文改坏。这是 skill 里专门写了提醒的地方。

## 安装

```bash
git clone https://github.com/<你的用户名>/gzh-editor-in-chief.git \
  ~/.workbuddy/skills/gzh-editor-in-chief
```

放到 `~/.workbuddy/skills/`（或项目的 `.workbuddy/skills/`）下即可，重启会话后生效。

## 用法

直接说人话触发，或显式点名：

- 「这篇文章帮我过一遍责任编辑」
- 「字数超了，怎么砍」
- 「审一下这篇观点文」
- 「这是干货文，检查一下」

## 输出

报告直接打在终端，不生成文件。三档打回等级：

- **P0 合规** —— 触碰红线，直接打回
- **P1 不通过** —— 结构性问题，必须改
- **P2 建议改** —— 逐处建议，由作者定

## 可选依赖

本 skill **可独立运行**，但装了以下 skill 会更完整（它们提供本skill 引用但不内嵌的口径）：

| Skill | 作用 | 缺失时|
|---|---|---|
| 议论文体风格锁 | 议论文专项 24 项的口径来源 | 24 项仍能跑，但风格判定会略粗 |
| 散文风格锁 | 散文/混合体的风格口径 | 跑 12 维通用即可 |
| 错别字检查 | 字面层校对 | 需自行检查错字 |
